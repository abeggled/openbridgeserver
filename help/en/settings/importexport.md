# Data Management

The Data Management tab lives in the Admin GUI under **Settings → Data Management**. This
tab is only visible and usable for administrators.

## Create / restore backup (JSON) {#settings-importexport-config}

**Create backup** — downloads all data points, bindings, adapter instances, KNX group
addresses, logic graphs, visu, custom nav links, app settings, hierarchy, icons, and the
FontAwesome API key as a single JSON file.

**Restore backup** — uploads such a JSON file again. This uses **upsert semantics**: existing
entries are updated, missing ones are created — entries deleted since the backup was taken
are left untouched (not a full restore, see below for that).

## Create / restore database backup (SQLite) {#settings-importexport-db}

**Create database backup** — downloads the full SQLite database, including all history data
and configuration.

**Restore database** — uploads such a file and **completely overwrites all current data**
(not an upsert like above):

- All current data points, bindings, adapters, and logic graphs are replaced.
- History data is replaced with the content of the uploaded file.
- Adapters and the logic engine are automatically restarted afterward.
- Any data not included in the backup is lost.

This is the path for a truly complete restore (e.g. recovering from a total loss), as opposed
to the additive JSON backup above.

## Backup / restore message archive {#settings-importexport-messagearchive}

Same idea as the database backup above, but for the **separate** SQLite database that holds
message archives. Restoring completely replaces all current message archives and messages —
the actual OBS configuration database is left untouched.

## Autobackup {#settings-importexport-autobackup}

Daily automatic JSON backup of all configuration data (same content as "Create backup"
above), stored locally in the data directory. The time of day and how many days of backups to
retain are configurable; "Back up now" triggers an immediate backup outside the schedule.

**Restore** — selects a saved autobackup and restores it, with the same upsert semantics as
the regular JSON restore above: existing entries are updated, missing ones created, entries
deleted since the backup remain untouched. For a truly complete restore from an autobackup:
factory-reset first (Danger Zone tab), then restore.

## Import KNX project {#settings-importexport-knx}

Imports an ETS project file (`.knxproj`, optionally password-protected). All group addresses
(GA, name, DPT) are stored, become available as search suggestions in the binding form
afterward, and are included in backups — regardless of whether data points are created from
them.

**Create/update data points** (optional) — creates data points for the imported group
addresses, linked to a chosen KNX adapter instance. Direction is selectable:
read/write, read-only (from adapter), or write-only (to adapter).

**Create hierarchies** (optional, independent of the data points) — generates hierarchy nodes
from the ETS project's structure, in up to three modes at once: topology (group address
structure), buildings/rooms, and trades — buildings/rooms and trades are only created if the
ETS project actually contains those structures. "Replace existing ETS hierarchies from this
import" only replaces hierarchies automatically generated by an earlier ETS import; manually
created hierarchies are left untouched. "Automatically link created data points to hierarchy
nodes" requires data points to be created in the same import.
